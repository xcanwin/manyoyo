# 安全须知

MANYOYO 降低风险，但不是“绝对安全”。使用前请了解下面几点；其他页面遇到风险只放一句话并链接到这里。

## 隔离的边界

- 主要隔离手段是**容器，不是虚拟机**；容器逃逸类漏洞不在 MANYOYO 的防护范围内。
- Agent 能访问你**挂载进容器的目录**和**传给它的环境变量**（包括 API Key）。工作目录只挂需要的，不要把家目录整个挂进去。
- 容器默认可以访问网络，Agent 可以访问你允许它访问的任何地址。
- 会话历史、日志和配置保存在你本机的 `~/.manyoyo/`，Key 只存在这里。

## YOLO / SOLO 模式

`-y` / `--yolo` 会跳过 Agent 的权限确认，Agent 可以不经询问执行命令、改文件。只在可控环境（容器内、可丢弃的工作目录、有备份的仓库）里使用。

## 容器模式

- `common`（默认）：标准容器。
- `dind`：容器内可以再跑容器，使用 `--privileged`，隔离明显减弱。
- `sock`：挂载宿主机 Docker socket，等于把宿主机的容器控制权交给容器内的 Agent，**不属于强隔离**，只在必须操作宿主机 Docker 时使用。

详见[容器模式](../reference/container-modes.md)。

## 对外监听

`manyoyo serve` 默认只监听 `127.0.0.1`。用 `0.0.0.0` 对外监听时必须设置强密码（`-P` 或 `serverPass`），并用防火墙限制来源；所有页面和接口默认都需要登录。认证细节见[网页服务与远程访问](./web.md)。
