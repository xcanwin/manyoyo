# 接入国内模型服务

在网页「系统设置 → 模型服务」里管理 Key，不用手改配置文件，界面上也不出现变量名。一项 = 一套“服务商 + Key”，保存在 `~/.manyoyo/manyoyo.json` 的一个运行配置（`runs.<名字>`）里，Key 只显示末 4 位。

## 网页操作三步

1. 打开「系统设置 → 模型服务」，点「添加模型服务」。
2. 选 Agent 和服务商（默认是 Claude Code CLI，要加 Codex CLI 先点「Codex CLI」），粘贴 Key，保存。服务商自带的地址、模型和附加设置会自动填好；名字留空会自动生成（如 `codex-deepseek`，重复了加数字）。保存后会自动测试一次（让模型真的执行一条命令并读回结果），之后也可以随时点列表里的「测试」。
3. 新建容器或快捷对话时，在运行配置下拉里选它，显示成“Claude Code CLI · 智谱 GLM”。

已经有 Claude Code 的 Key 时，列表下方的虚线框里会出现“智谱 GLM 的 Key 也能给 Codex CLI 用”，点「一键添加」即可，不用再填一遍；添加后会自动测试，出现绿字“连接成功”就是通了。点「从本机导入」可以读取本机已有的 Key、地址和模型（只读取，不会挂载本机目录，也不读取登录凭据）。

## 测试结果怎么看

- 绿字“连接成功”：Key 能用，模型也能执行命令。
- 红字“认证失败”：Key 不对（或用错了套餐），点「编辑」改 Key；“详情”里是服务端原话。
- 红字“额度不足”：账户余额或套餐额度用完了，或者套餐 Key 用在了按量计费的地址上。
- 红字“模型名不存在”：检查模型名。
- 红字“能连通，但模型没有执行命令”：这个服务或模型调不了工具，换一个模型试试。

## 服务商

| 服务商 | Claude Code CLI | Codex CLI | 说明 |
|---|---|---|---|
| 智谱 GLM | ✓ | ✓（`glm-5.3`） | 套餐 Key 与按量 Key 不通用，用错会报额度不足 |
| DeepSeek | ✓ | ✓（`deepseek-flash`） | 在 DeepSeek 开放平台创建 Key |
| Kimi | ✓ | ✓ | Codex 需要自己填模型名 |
| 火山方舟 | ✓ | ✓ | Codex 需要自己填模型名 |
| MiniMax | ✓ | ✓ | Codex 需要自己填模型名 |

各家的官方说明链接在添加页服务商按钮下方。其它兼容服务选「自定义地址」。

## 要注意的

- **Codex 必须指定模型名**：Codex 不会从环境变量读模型，网页和命令行会自动带上你填的模型；没填模型的兼容服务不能保存。
- **智谱 + Claude Code 要关掉“工具搜索”**：不关的话模型看不到 Bash，什么命令都执行不了。预设会自动写入 `ENABLE_TOOL_SEARCH=false`，手写配置时请自己加上。
- **官方 OpenAI Key 的用法没有验证过**，建议先在网页里「测试」再用。

## 订阅登录

- **Claude Code**：在任意有浏览器的电脑上运行 `claude setup-token`，把得到的长期令牌粘贴到“订阅登录”里；也可以建好会话后在容器的终端里运行 `claude`，按提示登录（凭据只在那个容器里）。保存令牌时会删掉同一项里的 API Key 和 Base URL，否则 Claude Code 会优先用 Key。
- **Codex**：在容器的终端里运行 `codex login --device-auth`，按提示用浏览器登录。登录只在那个容器里有效，换容器要重新登录。

MANYOYO 不会复制宿主机的登录凭据到容器里。

## 改了 Key 之后，已有容器怎么办

容器创建时会把 Key 写进它自己的环境变量，改配置不会自动跟着变。编辑模型服务时，如果有容器还在用旧 Key，会提示并默认勾选“同时更新这些容器”，下一轮对话就用新 Key，不用重建容器。删除模型服务只删配置，不影响已有容器。

## 命令行

`manyoyo setup` 已有配置时会新增一套（名字形如 `claude-zhipu`），不会覆盖原来的；用 `manyoyo run -r <名字>` 启动。
