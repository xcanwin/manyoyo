# 管理容器的环境变量、网络与自启动

新建容器时可以设好环境变量、网络（含端口暴露）和自启动脚本；容器跑起来之后，在网页工作台的 **更多标签页 → 容器** 里随时修改，**不需要重启或重建容器**。风险与边界见[安全须知](./security.md)。

::: tip 旧容器
升级前创建的容器没有这些能力，「容器」页会提示“创建于旧版本，重建后可用”；它们的行为不变，也不会被迁移。
:::

入口是顶栏「…」（更多标签页）菜单里的 **容器**。页面从上到下依次是：环境变量、网络（含端口暴露）、自启动（自启动要等网络规则下发完成才运行，所以排在网络后面）；三块各有**独立的保存按钮**。新建容器的弹窗里同样按这个顺序设置。

## 什么时候生效

| 改动 | 生效时机 |
| --- | --- |
| 环境变量 | 下一条命令 / 下一个新打开的终端；已在运行的进程和已经打开的终端不受影响 |
| 网络规则 | 保存后约 2 秒内，容器不重启 |
| 端口暴露 | 点「保存网络规则」后立即；serve 重启后自动恢复 |
| 自启动脚本 | 容器下次启动；也可点「立即运行」 |

## 环境变量

- 这一块分两部分：**环境变量文件**（宿主机上的绝对路径，可添加多个）和**直接填写的变量**。文件每次执行命令时重新读取，所以改了文件下一条命令就生效；多个文件按顺序读取、后面的覆盖前面的，直接填写的变量优先于文件。页面会显示每个文件读到几个变量、哪些行被跳过。自启动脚本看到的是容器每次启动（下发规则）时文件内容的快照。
- 直接填写的变量：表格视图默认遮罩名字含 `KEY` / `TOKEN` / `SECRET` / `PASSWORD` / `AUTH` / `CREDENTIAL` 的值，点眼睛才显示；文本视图是 `KEY=VALUE` 每行一项。
- **语法只有一种**（文本视图、环境变量文件、容器里的 `/run/manyoyo/env` 都一样）：与 docker / podman 的 env-file 一致——不展开变量、不执行命令，值里的空格不需要引号（`KEY=abc 123`）；同时兼容 shell / dotenv 的写法：可以带 `export ` 前缀，值两端成对的引号会被去掉（`KEY="abc 123"` 与 `KEY=abc 123` 等价）；`#` 只在行首是注释。表格里填的值写成文本时只在首尾有空白等必须时才加引号。
- 变量保存在本机 `~/.manyoyo/containers/<id>/box/env`，**不会写进容器配置**（`podman inspect` / `docker inspect` 看不到明文）。
- 容器里也可以直接编辑 `/run/manyoyo/env`（同样的 `KEY=VALUE` 格式），下一条命令起生效。页面上会提示“容器内已修改”，非法的行（例如 `1BAD=x`）会标红并被跳过。
- 新开的终端自动带上新变量；已打开的终端里执行 `reload-env` 即可生效（正在运行的进程不受影响）。
- 保存时如果容器里刚改过这个文件，页面会提示冲突并让你重新加载，不会悄悄覆盖。

## 网络

新建容器**默认收紧**：

- 禁止：宿主机的其他端口、局域网和私有网段、云元数据地址（`169.254.169.254`）、其他容器。
- 允许：公网；manyoyo 必需的端点（DNS、你机器上的上游代理、Playwright 浏览器服务、软件源镜像）。

在「网络」里可以：

| 我想… | 怎么做 |
| --- | --- |
| 让容器访问宿主机上的某个服务（例如本机的 Ollama） | 「允许访问的宿主机端口」添加一行，端口如 `11434`。宿主机服务要监听 `0.0.0.0`，只绑 `127.0.0.1` 的容器访问不到。在容器终端里验证：`curl --noproxy '*' http://host.containers.internal:11434/`（容器里常带代理环境变量，要加 `--noproxy`） |
| 访问局域网里的某个服务 | 「额外放行的 IP 规则」添加一行：IP `192.168.1.50`、端口 `8000` |
| 让容器 A 访问容器 B 的 7000 端口 | 在 **B** 的「允许其他容器访问我」里添加一行：来源容器 A、端口 `7000` |
| 只允许访问 github.com 等少数域名 | 出站切到「仅白名单」，「允许的域名」逐行添加（支持 `*.example.com`） |
| 临时把容器的 8080 端口暴露到宿主机 | 「端口暴露」添加一行：监听 `127.0.0.1`、宿主机端口 `18080`、容器端口 `8080`，保存后点那一行的「打开」 |
| 回到旧版行为 | 出站选「开放」（需二次确认），不加任何规则 |

新建容器时如果在环境变量里填了指向私有地址的 URL（如 `OLLAMA_BASE_URL=http://host.containers.internal:11434`、局域网里的模型网关），这些端点会自动写进规则，免得 Agent 一上来就连不上；规则在「网络」里看得到，也可以删。

### 域名白名单

「仅白名单」只让容器访问你列出的网站。容器的防火墙只放行到 manyoyo 网络里的一个专用小容器（过滤代理，宿主机上不开任何端口），其他出站一律被挡；容器里的浏览器、`curl`、Agent 会自动使用它，不需要额外设置。解析到私有 / 本机地址的域名一律拒绝（防止借它访问宿主机），需要时在「IP 规则」里显式放行；ssh、数据库等非 HTTP 协议也用「IP 规则」放行。

- **Agent 访问模型服务也走它**：模型服务的域名（如 `ANTHROPIC_BASE_URL` 的主机）必须在白名单里。新建容器时 env（含环境变量文件）里 URL 的域名会自动加进白名单；已有的容器切到「仅白名单」后，页面会把环境变量里出现的域名列成按钮，点一下加入。
- **网页打不开、点了没反应？** 打开「容器」页的**最近被拦截**：这里列出容器想访问却不在白名单里的网站（图片、CDN 等），点「允许」马上生效，不用重启。浏览器自己的后台请求折叠在「浏览器后台请求」里，可以不管。Agent 运行时有新网站被拦，对话里也会立即提示一次。
- 被拦的访问会收到 `403`。
- 代理容器由 manyoyo 自动创建和拉起，名字形如 `manyoyo-egress-xxxxxxxx`，不要手动删除或修改；它不依赖 `serve`，命令行和网页都能用。

### 端口暴露

暴露端口由 serve 在宿主机监听，再把每个连接转进容器；默认只绑 `127.0.0.1`。端口暴露和其他规则一样在「保存网络规则」时生效，新建容器时也可以直接填。绑 `0.0.0.0` 等于局域网 / 公网可见（取决于宿主机的网络与防火墙），页面会要求二次确认。端口被占用会明确报错。

### 部署在公网服务器上

下面这些端口监听 `0.0.0.0`，在公网服务器上等于对整个互联网开放（各自有凭据保护，但仍应在云安全组 / 防火墙里只放行需要的来源）：

| 端口 | 用途 | 建议 |
| --- | --- | --- |
| `serve` 的监听端口 | 网页服务 | 配强密码；对外时放在 HTTPS 反向代理后面，见[网页服务与远程访问](./web.md) |
| `8935` | Playwright 浏览器服务（headed 模式，token 保护） | 同上，不对外开放 |
| 你绑定 `0.0.0.0` 的暴露端口 | 容器里的服务 | 优先绑 `127.0.0.1`，再用 `ssh -L` 或 HTTPS 反向代理访问；确需对外时在防火墙里限制来源 IP |

## 自启动

在「自启动」里写一段 bash 脚本：容器每次启动（新建、重启、`podman machine` 重启后再启动）都会由容器内的 init 运行一次，输出追加到 `/run/manyoyo/autostart.log`（页面「查看日志」）。打开“serve 启动时自动拉起此容器”后，`manyoyo serve` 启动也会把这个容器启动起来。

脚本以 root 身份运行，工作目录是容器的默认目录，路径请按**容器内**的路径写（宿主机挂载目录对应的容器路径在「配置」页的 containerPath）。「立即运行」的输出不会自动显示，点「查看日志」查看；脚本失败也会写进这个日志，排错先看这里。

容器的 PID 1 是 manyoyo 自带的 init：会回收僵尸进程、响应停止信号（`stop` 不再等满 10 秒）。网络规则下发完成之前，自启动脚本和 Agent 都不会运行。

## 配置字段

新建容器时也可以写在 `manyoyo.json` 的全局或 `runs.<name>` 里，详见[配置文件](../configuration/config-files.md)：`autostart`（脚本文本）、`autostartOnServe`、`network`。命令行 `manyoyo run` 新建容器时同样会写入，并在启动 / 连接容器前下发网络规则；管理入口是网页。

## 常见问题

- **容器重启后规则会丢吗？** 不会丢：每次启动后 manyoyo 会重新下发，并且下发完成前自启动和 Agent 不会运行。serve 在运行时会监听容器启动事件，外部重启（`podman restart`）也会自动补下发。
- **提示“网络规则下发失败”？** 页面会显示原因，规则保持原样、容器保持“未放行”。常见原因是镜像里没有 `nft`（旧镜像，请升级镜像）或运行时不可用。
- **Docker 能用吗？** 能。macOS 上的 Docker Desktop 需要共享 `~/.manyoyo` 目录（默认已共享用户目录）。
