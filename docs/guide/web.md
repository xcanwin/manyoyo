# 网页服务与远程访问

本页讲 `manyoyo serve` 网页服务：怎么启动、怎么登录、怎么远程访问。风险与边界见[安全须知](./security.md)；SSH 机器上的 `ssh -L` 访问见[第一次使用](./first-run.md)。

容器跑起来后，可在「设置容器」标签页随时修改它的环境变量、自启动脚本和网络规则，见[管理容器的 env、网络与自启动](./container-manage.md)。

当前网页交互支持三种模式：`命令模式`、`AGENT 模式`、`交互终端`。其中 `AGENT 模式` 需要会话配置 `agentPromptCommand`（模板内必须包含 `{prompt}`）。

## 聊天里的小功能

- **发图片**：在 AGENT 模式的输入框里直接粘贴或拖入截图；手机点输入框左下角的「添加图片」从相册选。一次最多 5 张，每张不超过 10MB，支持 png、jpeg、gif、webp。图片存在容器的状态目录里，删除容器时一起删除。2.3.0 之前创建的旧容器没有这个目录，需要重建后才能发图片。能不能看懂图片取决于你用的模型。
- **模型地址被拦**：容器用了「仅白名单」等网络策略，而 AGENT 自己的模型地址不在白名单里时，聊天里会立刻提示「模型地址 xxx 被网络策略拦截」，点「允许并重试」即可放行并重发刚才那条。
- **回退**：点自己发的提示词右下角的「回退到这里」按钮，可选「恢复对话和文件」「只恢复对话」「只恢复文件」，改动前会先列出要改回、删除、恢复的文件。Claude 能精确回到那一轮；其它 agent 会用剩下的聊天记录开新会话。每一轮前后都会给工作目录拍快照（遵守 `.gitignore`；目录大到 3 秒拍不完，这一轮就不能回退文件；没被 `.gitignore` 忽略的单个文件超过 20MB、或快照累计超过 1GB 时也不拍。快照随容器一起删除，大文件请放进 `.gitignore`）。回退本身也能撤销：它会先拍一张「回退前」的快照。
- **按轮看改动**：「改动」页可以切到「按轮」，选一轮看它改了哪些文件；工作目录不是 git 仓库（比如快捷对话）时默认就是这个视图。
- **删掉某段对话**：用「回退到这里」选「只恢复对话」，这一组及之后的对话会删掉，agent 也会忘掉它们，文件不动。

## 监听地址与启动方式

`serve` 仅支持 `<ip:port>` 格式，例如 `127.0.0.1:3000`、`0.0.0.0:3000`。

默认监听地址为 `127.0.0.1:3000`。

```bash
# 仅本机访问（默认）
manyoyo serve

# 指定监听地址
manyoyo serve 127.0.0.1:3000

# 局域网访问（需配合强密码与防火墙）
manyoyo serve 0.0.0.0:3000 -U admin -P 'StrongPassword'

# 后台启动
manyoyo serve 127.0.0.1:3000 -U admin -P 'StrongPassword' -d

# 后台启动并自动生成密码（会直接打印本次随机密码）
manyoyo serve 127.0.0.1:3000 -d

# 停止指定后台服务
manyoyo serve 127.0.0.1:3000 --stop

# 停止本机所有后台服务（不写监听地址）
manyoyo serve --stop

# 重启指定后台服务
manyoyo serve 127.0.0.1:3000 -U admin -P 'StrongPassword' -d --restart
```

## 认证参数优先级

网页认证参数包括 `serverUser` 与 `serverPass`，支持命令行、配置文件、环境变量。

优先级如下：

`命令行参数 > runs.<name> > 全局配置 > 环境变量 > 默认值`

对应环境变量：

- `MANYOYO_SERVER_USER`
- `MANYOYO_SERVER_PASS`

默认值：

- `serverUser`: `admin`
- `serverPass`: 未显式设置时，启动时自动生成随机密码并输出到终端

## 认证网关行为

`serve` 模式采用全局认证网关，除登录相关放行路由外，其余页面和接口默认要求登录。

当前匿名放行路由：

- `/auth/login`（`GET` 是登录页，`POST` 是登录接口）
- `/auth/logout`

未登录访问任何页面路径都会跳转到 `/auth/login`，接口与 `/auth/*` 则直接返回 `401`。

## 输入框

模式（💬 Agent 对话 / 系统命令）、模型、发送和停止都是输入框里的图标按钮，鼠标悬停能看到说明。在 Agent 对话里：

- 开头打 `/` 会列出能用的命令，每条带一句说明。新 AGENT 不用先发一句也有；网页自己处理的命令所有 Agent 都能用，Claude Code 另外会列出它的技能和内置命令。
- 打 `@` 会列出工作目录里的文件，选中后插入相对路径。
- ↑↓ 选择、Enter 或 Tab 确认、Esc 关闭。

## 对话里的快捷功能

下面这些都在输入框一带，也可以打 `/命令` 触发。网页命令按下表处理，其它 `/xxx` 照旧原样发给 Agent。

| 命令 | 适用 | 作用 |
|---|---|---|
| `/model` | 全部 | 打开模型菜单 |
| `/effort [级别]` | Claude、Codex | 设置推理强度；不带参数打开模型菜单 |
| `/status` | 全部 | 打开 Agent 详情 |
| `/diff` | 全部 | 查看工作目录里的改动 |
| `/clear` | 全部 | 在这个容器里新建一个 AGENT |
| `/copy` | 全部 | 复制最后一条回复 |
| `/fork` | 全部 | 从最新处分叉出一个新的 AGENT |
| `/btw <问题>` | Claude、Codex | 侧问：带着上下文问一句，不打断主任务 |
| `/recap` | Claude、Codex | 用一句话回顾刚才做到哪 |
| `/review` | 全部 | 让 AI 审查未提交的改动 |
| `/plan` | Claude | 打开 / 关闭计划模式 |
| `/skills`、`/mcp` | Claude、Codex | 查看容器里的技能和 MCP |

- **推理强度**：在模型菜单的最下面，只列当前模型支持的档位；选“默认”就用容器环境变量和配置里的设置。当前模型不支持或不知道支持哪些时不显示（比如 Codex 接了自定义模型）。切换模型后，如果新模型不支持当前档位会自动回到默认。网页上选的档位优先于容器环境变量里设的 `CLAUDE_CODE_EFFORT_LEVEL`。
- **上下文占用**（仅 Claude Code）：模型菜单旁边的小读数，如“4.5k · 0%”（手机上只显示百分比），点开看占用、上一次请求里有多少输入来自缓存。空闲超过 5 分钟会提示“下次发送可能要重新缓存（更贵）”；第三方服务的缓存时长未知，所以只说“可能”。每一轮结束时更新一次。
- **侧问 `/btw`**：答案显示在输入框上方的浮层里，不进对话记录，主任务可以同时在跑；关闭浮层会取消这次提问。同一个 AGENT 同时只能问一个。Claude 带着已有对话回答，也不会新增会话文件。
- **分叉**：点自己发的提示词右下角的分叉图标，或打 `/fork`（从最新处），会先弹窗说明并确认。同一个容器里会新建一个 AGENT，带着那一轮之前的对话，那条提示词放进新 AGENT 的输入框；原来的 AGENT 不变，工作目录文件也不复制（两边共用同一个目录）。Claude 精确分叉，其它 Agent 用剩下的聊天记录开新会话。任务进行中不能分叉。
- **审查改动**：「改动」页工具栏的“审查改动”按钮或 `/review`。Claude 有自带的 `/code-review` 就用它，否则发一句固定的审查提示词，都是普通的一轮对话；任务进行中或有排队内容时按钮不可用。
- **计划模式**（仅 Claude Code）：输入框里的“计划模式”按钮（打开后按钮变深色并提示“已切换到计划模式”）或 `/plan`，这一轮只出计划、不改文件，发送一次后自动关闭。回复下方会出现“按计划执行”。计划模式下 Claude 不能向你提问选选项（网页对话里没有这个工具），需要补充时它会直接用文字问。
- **回顾**：打开一个空闲超过 30 分钟的 AGENT 时，消息流底部会出现一行灰色“回顾：……”，可以关掉；`/recap` 手动生成。
- **技能与 MCP**：顶栏 ⋯ → 容器组 → “技能与 MCP”，只读列出容器里 Claude Code、Codex 的技能和 MCP 服务器状态（Claude 的 MCP 会真的去连一次，可能要几秒）。容器里看不到宿主机的 skill：把项目目录挂进容器（项目里的 `.claude/skills` 会自动生效），或复制到容器的 `~/.claude/skills/`。
- **自动标题**：发出第一句话后，Claude Code、Codex 会用一次很便宜的模型调用起一个十几个字的标题；备注、`/rename` 起的名字优先。每个 AGENT 只试一次，失败也不重试。
- **标签页标题**：当前对话有任务在跑时，标题前面会有 `◐`。

## 任务进行中追加提示词

Agent 在跑任务时，输入框不会被禁用，可以继续输入。输入内容后，发送键左边会出现“插入时机”按钮，点它选择何时生效（记住上次的选择，输入框的提示文字也会写明当前时机）：

- 立即插入：打断当前这一轮，马上带着新提示词接着做（已做完的工作保留）。
- 当前这一步结束后插入：等这一次工具调用或这段说明结束再打断；等了 2 分钟还没等到就改为立即插入。
- 这一轮结束后发送：排队，等这一轮结束后自动发出（默认）。

排队中的提示词显示在消息流底部，可以撤回（✕）或编辑（✎）。点“停止”只停当前这一轮，排队的提示词会保留，可以取消或点“继续发送”。系统命令模式不支持追加。

Agent 派出的子 Agent 和任务清单也会显示在“执行过程”里：子 Agent 默认收起成一行，点开看它做了什么；任务清单只显示一块最新状态。Agent 还在执行时，它正在说的话显示在“执行过程”里，回复框等这一轮结束才出现，里面就是最终结论。执行过程右侧的“对齐到底部”按钮会让这段过程的底部一直贴着窗口底部，自己滚动一下就取消。

## 会话、改动与提醒

- 会话名称：优先用备注，其次是 Agent 自己起的标题（`/rename`），再是发出第一句话后自动生成的标题（Claude Code、Codex），最后是第一条消息。点顶栏的名称可以改名，清空就恢复自动名称。
- 置顶：容器和 AGENT 都可以在各自的 ⋯ 菜单里置顶。置顶的容器排在容器列表最前；AGENT 置顶只影响它在容器里的顺序。
- 排序：侧栏的 ⇅ 按钮可以按名称、创建时间或修改时间（默认）排序；容器层排容器，进入容器后排 AGENT，置顶的始终在最前。选择会记在浏览器里。
- 顶栏 ⋯ 里按归属分组：聊天属于 AGENT；文件、终端、改动、技能与 MCP、设置容器属于容器。“改动”列出工作目录所在 git 仓库的改动，点文件看 diff。
- 回复里的图片：Agent 用 Markdown 图片写容器内路径（如 `![截图](/root/shot.png)`）就能直接显示。写在回复里的绝对路径可以点开，在文件页查看。
- 任务结束提醒：页面在后台时任务结束，标签页标题前会出现 `(1)` 这样的计数；在“系统设置 → 页面”里可以打开浏览器通知（需要 HTTPS 或 localhost）。
- 离开一阵子再回来，或者网络恢复后，顶栏会显示同步进度，同步完显示“已同步”。

新建容器：默认的容器名是 `my-easy-{now}`，宿主机目录和容器内目录是 `{quickChatPath}/{now}`（`{now}` 为 `年月日-时分秒`，`{quickChatPath}` 为快捷对话目录，没配置就是 `~/.manyoyo/work`）；这三项都可以在“系统设置 → 基础”里改。点“创建并进入”时才会真的建目录。

磁盘占用：删除容器不会删掉它在宿主机上的工作目录。“系统设置 → 维护 → 磁盘占用”按目录列出占用，容器已删除或无人使用的工作目录可以直接清理；你自己的项目目录、配置里写死的挂载目录、里面挂着其它磁盘的目录只展示或拒绝删除。每个目录都能点开查看里面的文件，页面下方还能清理已删除容器留下的对话历史。“已删容器且删历史的空目录”分类可以一键清掉所有空目录；在侧栏删除容器并选“连同历史一起删除”时，如果它的工作目录在 MANYOYO 工作目录里且是空的，也会一并删除。

网页里执行 Agent 时会附上系统提示词，告诉它回复显示在网页里、图片怎么写。在“系统设置 → Agent → 系统提示词”里可以关掉默认系统提示词，或写补充系统提示词（配置字段 `agentInstructions`）；它们只决定之后新建容器的初始内容。新建容器时可以直接改，已有容器在“设置容器”里改，互不影响。

## 导出与导入

把容器连同对话一起搬到另一台机器（或同一台机器的新镜像版本）。入口：侧栏顶部的下载图标（悬停提示“导出 / 导入”，点开选“导出容器…”或“导入容器…”），或容器 ⋯ 菜单里的“导出…”。只想换机器后接着聊，选“标准”就够了（“轻量”也能接着聊，但不带工作目录）。

**导出**：选容器和档位，开始导出。

| 档位 | 包含 |
|---|---|
| 轻量 | 网页聊天记录、Agent 会话记录、容器设置（环境变量、自启动脚本、系统提示词、网络规则）。小，导入后就能接着聊 |
| 标准（推荐） | 轻量 + 聊天里的图片、Agent 的技能 / MCP / 设置 / 记忆、宿主机上的工作目录 |
| 完整 | 标准 + 容器里装的软件和全局包、按轮回退的文件快照。系统层改动只在对方镜像版本相同时还原 |
| 自定义 | 手动勾选内容，勾成某一档就自动高亮那一档 |

- 缓存、临时目录（`/tmp` 里 Agent 浏览器工具的截图、二维码等产物 `/tmp/.playwright-cli` 除外，随“标准”及以上带上）、挂载进来的目录（工作目录之外的额外挂载只记录路径、不带内容）永远不导出。
- **密钥默认一起导出**（否则新机器上没法直接对话），文件里有你的 API Key，请妥善保管；也可以取消勾选：API Key、令牌类环境变量和各 Agent 的登录凭据（如 Claude 的 `.credentials.json`、Codex 的 `auth.json`）都不会进文件，导入后在“设置容器”里补 Key、重新登录。
- 保存方式：**直接下载**（默认）由浏览器接收，服务器不占磁盘，但要保持页面打开直到开始接收；**保存到服务器**放在 `~/.manyoyo/exports/`，可以关掉页面，会占用服务器磁盘（开始前会检查剩余空间）。
- 导出期间这些容器会被暂停（结束后恢复原来的状态；个别容器暂停后读不到文件时会自动改成不暂停直接读），聊天、终端、文件、设置和删除暂时不可用，侧栏卡片转圈，点卡片看进度，可以取消。AGENT 正在执行时不能导出。
- 压缩：“快速”（zstd 3，默认）或“更小”（zstd 10，约小 20%、慢 4 倍）。文件名 `manyoyo-export-年月日-时分秒.tar.zst`，用 `zstd -d` 加 `tar t` 就能查看内容。

**导入**：“导出 / 导入 → 导入容器…”，选本机文件，或选 `~/.manyoyo/exports/` 里的文件（文件很大时先用 `scp` 放到服务器上这个目录，避开反向代理的上传大小限制）。先只读文件开头显示清单，再逐个容器确认：

- 导入后的容器名（重名会自动换名）、导入后的容器备注（默认沿用原来的，可改可清空）、本机的工作目录（默认放在快捷对话目录下、以新容器名命名的子目录；必须是还不存在或为空的目录）。本机目录可以随便换，但**容器里的路径保持原样**（弹窗里会写出来），Agent 才能接着聊。
- 镜像：“与原来相同”，或“用本机默认版本”。
- 归档里的高风险设置（sock / dind 模式、额外挂载、端口映射、自启动脚本、环境变量文件、自定义网络规则）默认都不生效；镜像名不是 manyoyo 的镜像时一律改用本机默认镜像，勾选后才会带上；导入时 `first` 首次命令永远不执行。
- 导入完成后新容器出现在侧栏里（不会自动跳过去）。
- 文件边收边解包，不先存成临时文件；上传中断、文件不完整或取消，会自动撤销本次导入建的容器、目录和历史，不留半个容器。

**换镜像版本迁移**：用“标准”档导出，导入时选“用本机默认版本”。系统层改动不带，用户数据、Agent 记录、工作目录、聊天记录全带，容器按新镜像重建，可以接着聊。确认没问题后再自己删掉旧容器。

## 网页前端

`serve` 模式的 Web 界面由 shadcn/ui 前端提供。

- 默认地址：`http://127.0.0.1:3000/`。未登录会跳转到 `http://127.0.0.1:3000/auth/login`，登录成功后回到 `/`
- 登录走 `/auth/login` 接口和 cookie
- 源码在仓库根目录的 `frontend/`，是独立的 Vite + React + TypeScript 项目；它使用 ES Modules，本项目其余 Node 代码仍遵循 CommonJS 约定

首次参与开发需要单独装一次它自己的依赖（体积较大，与根目录 `npm install` 分开，不会拖慢日常开发）：

```bash
cd frontend && npm ci && cd ..
```

之后按需选择：

```bash
# 只想看当前构建效果：手动构建一次，再照常启动 my serve 预览
npm run build:web
manyoyo serve

# 改 frontend/src 下的代码并实时看效果（HMR），两个终端：
manyoyo serve                # 终端一：真实后端（容器、会话、终端 WebSocket）
npm run dev:web       # 终端二：Vite 开发服务器，默认把 /api、/auth 代理到 127.0.0.1:3000
```

`my serve` 监听地址不是默认的 `127.0.0.1:3000` 时，用 `MANYOYO_SERVE_URL` 环境变量覆盖 `dev:web` 的代理目标。

发布时（`npm publish`/`npm pack`）会自动重新构建 `frontend` 并把产物打进 `lib/web/index.html`；生产环境运行 `my serve` 不需要 Node 之外的任何前端工具链。

## 登录与 API 访问示例

```bash
# 1) 登录并保存 cookie
curl --noproxy '*' -c /tmp/manyoyo.cookie \
  -X POST http://127.0.0.1:3000/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"StrongPassword"}'

# 2) 带 cookie 访问接口
curl --noproxy '*' -b /tmp/manyoyo.cookie \
  http://127.0.0.1:3000/api/sessions

# 3) 登出
curl --noproxy '*' -b /tmp/manyoyo.cookie \
  -X POST http://127.0.0.1:3000/auth/logout
```

## 最小安全基线

- 优先使用 `127.0.0.1` 监听，仅本机访问
- 使用 `0.0.0.0` 时必须设置强密码，并通过防火墙限制来源 IP
- 不要把明文密码写入共享脚本；优先放到受保护配置文件或环境变量
- 定期更换 `serverPass`，共享环境使用独立账户与独立口令

## 常见问题

### 返回 `401 Unauthorized`

排查顺序：

1. 确认已完成 `/auth/login` 并带上 cookie
2. 确认 `-U` / `-P` 与配置项一致
3. 使用 `manyoyo config show` 检查 `serverUser`/`serverPass` 的最终来源
