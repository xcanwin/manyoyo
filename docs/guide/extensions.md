# 共享技能与 MCP

在宿主机维护一份技能和 MCP，新容器会自动带上，已有容器可以按需同步。入口：顶栏 ⋯ → 容器组 → “技能与 MCP”。

## 共享库在哪

```
~/.manyoyo/extensions/
  skills/
    common/<名称>/SKILL.md    # Claude 和 Codex 都能用
    claude/<名称>/SKILL.md    # 只给 Claude
    codex/<名称>/SKILL.md     # 只给 Codex
  mcp.json                    # 共享 MCP 配置（含密钥，权限 0600）
```

删除容器不会删除共享库。共享库只管理由它添加的条目；容器里手动添加的技能和 MCP 不会被覆盖或删除。

## 新容器与已有容器

- 新容器：整个 `skills/` 目录以只读方式挂进容器，并在容器 home 里建立指向共享目录的链接，所以共享库更新后新容器马上就能用到新内容。容器改不了共享文件。
- 已有容器（创建时还没有共享库）：点“同步到当前容器”把内容复制进去；共享库更新后需要再同步一次。
- 同名的目录或 MCP 如果不是共享库添加的：跳过并显示冲突，不覆盖。复制模式下，共享库会在自己复制的技能目录里写一个 `.manyoyo-managed` 标记文件；同步时只删除“有标记且标记里的内容校验值对得上”的副本。标记丢了或对不上（例如你把它换成了自己的目录），就不删除，只记冲突。技能目录里的其它文件同样受单文件 1 MB、单个技能 20 MB 的限制；超限或含有符号链接的技能会整个跳过（列表里标“超过大小上限”），不参与内容校验，也不会同步，避免大文件拖慢扩展列表。

## 密钥与安全提示

- **共享技能是代码**：每个 Agent 都会读到它，技能里的脚本和说明可能影响 Agent 的行为。添加前请确认内容可信。
- **共享 MCP 的密钥对所有使用它的容器可见**：`mcp.json` 里的 `env` / `headers` 会下发到每个容器，容器里的 Agent 能读到。编辑时值留空表示保留原值；接口和界面只显示 key 和最后 4 位。
- **MCP 命令在容器里执行**，受容器的网络策略限制。如果 server 需要访问某个域名，请同时在网络规则里放行；网络失败不是 MCP 配置错误。
- **项目里的配置不会自动启用**：工作目录里的 `.mcp.json`、`.claude/skills` 由仓库提供，界面标“项目提供”，需要你在容器里确认；不会自动批准，也不会加进共享库。

## Claude 与 Codex 的差异

- stdio 两边都支持；SSE 只支持 Claude；Codex 的 HTTP 不支持自定义 headers，认证用 `bearerTokenEnvVar`（只存环境变量名，值请在容器 env 里设置）。
- 测试连接：Claude 会真实连接（最长约 30 秒）；Codex 只能确认“已配置”，不做连接测试。
- MCP 的 OAuth 登录不由 MANYOYO 管理。需要登录时，在容器终端里执行 Agent 自己的登录命令。

## 导出与导入

共享库本身不在容器里，不随容器导出。只读挂载方式创建的链接在导出时跳过；复制方式复制进容器 home 的副本会随容器导出。容器里已经下发的 MCP 配置可能含密钥，导出时会按字段清空。
