# 共享技能与 MCP

在宿主机维护一份技能和 MCP，新容器自动带上，已有容器可以按需同步。入口：顶栏 ⋯ → 容器组 → “技能与 MCP”。

## 共享库在哪

```
~/.manyoyo/extensions/
  skills/
    common/<名称>/SKILL.md    # Claude 和 Codex 都能用
    claude/<名称>/SKILL.md    # 只给 Claude
    codex/<名称>/SKILL.md     # 只给 Codex
  mcp.json                    # 共享 MCP 定义（含密钥，权限 0600）
```

删除容器不会删除共享库；共享库只管理自己下发的条目，容器里手动添加的技能和 MCP 不会被覆盖或删除。

## 新容器与已有容器

- 新容器：整个 `skills/` 只读挂进容器，容器 home 里建立指向共享目录的链接，所以共享库更新后新容器直接是新的。容器改不了共享文件。
- 已有容器（创建时还没有共享库）：点“同步到当前容器”把内容复制进去；共享库更新后需要再同步一次。
- 同名但没有被共享库管理的目录 / MCP：跳过并显示冲突，不覆盖。

## 密钥与信任边界

- **共享技能是代码**：它会被每个 Agent 读到，技能里的脚本和说明可能影响 Agent 行为。添加前请确认内容可信。
- **共享 MCP 的密钥对所有使用它的容器可见**：`mcp.json` 里的 `env` / `headers` 会下发到每个容器，容器里的 Agent 能读到。编辑时值留空表示保留原值；接口和界面只显示 key 和末 4 位。
- **MCP 命令在容器里执行**，受容器的网络策略约束。如果 server 需要访问某个域名，请同时在网络规则里放行，别把网络失败当成 MCP 配置错误。
- **项目级配置不自动信任**：工作目录里的 `.mcp.json`、`.claude/skills` 由仓库提供，界面标“项目提供”，需要你在容器里确认；不会自动批准、不会加进共享库。

## Claude 与 Codex 的差异

- stdio 两边都支持；SSE 只支持 Claude；Codex 的 HTTP 不支持自定义 headers，认证用 `bearerTokenEnvVar`（只存环境变量名，值请在容器 env 里设置）。
- 测试连接：Claude 会真实连接（最长约 30 秒）；Codex 只能确认“已配置”，不做连接测试。
- MCP 的 OAuth 登录不由 MANYOYO 管理，需要登录时在容器终端里执行 Agent 自己的登录命令。

## 导出与导入

共享库本身不在容器里，不随容器导出。挂载模式的链接在导出时跳过；复制模式复制进容器 home 的副本会随容器导出。容器里已下发的 MCP 配置可能含密钥，导出时会按字段清空。
