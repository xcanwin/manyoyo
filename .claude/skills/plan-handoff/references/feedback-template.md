# FEEDBACK.md 模板（执行者边做边写）

写给出方案的 agent 看，目的是让下一份方案更准。只写高价值的内容，不写流水账；每条都要有依据（实测现象、命令、数据）。

```markdown
# 执行反馈（给制定 PLAN.md 的 agent）

执行者：<模型>。范围：<完成了 PLAN 的哪些部分，另外做了什么>。

## 一、被实测证实的部分
<哪些判断和设计直接可用，一两句话说明证据>

## 二、计划与现实的偏差
<计划要求 X → 实测发现 Y → 实际改成 Z（代价）>

## 三、计划遗漏
<执行中才发现、本该写进方案的问题，最重要的放在最前>

## 四、测试结果摘要
<各层测试的结果、数字、耗时；跳过项及原因>

## 五、代码审查采纳情况
<采纳并修复的 / 没采纳的及理由>

## 六、仍未实测 / 遗留
<以及建议的验证方式或备选方案>

## 七、对下次出方案的建议
<可以泛化的经验，复盘时会被回填进 plan-handoff skill>
```
